## Branch and PR workflow

- Base every feature branch on `dev` (not `main`).
- One plan → one PR to `dev`.
- Commit often (every passing test), per the house style in `docs/AI_RULES.md`.
- Merge order to `dev`: 01 → 02 → 03 → 04 → 05 → 06. Plans 05 and 06 can swap if convenient.

## Tech stack reminders

- **Backend:** Python 3.12+ (pyproject currently says 3.14; plan 06 fixes this), FastAPI, `kicad_sch_api`, `litellm`, `httpx`, `pydantic`, `pytest`.
- **Frontend:** React 19, Vite (rolldown), Tailwind v4, TypeScript strict.
- **Tests:** `pytest` for backend. No frontend test framework today — plans only add tests there when behavior is non-trivial (plan 04 adds one).

## How to execute

For each plan, use one of:

- **Subagent-driven execution** (`superpowers:subagent-driven-development`) — fresh subagent per task, review between tasks.
- **Inline execution** (`superpowers:executing-plans`) — batch with checkpoints.

Plans use checkbox (`- [ ]`) tracking so either harness works.
